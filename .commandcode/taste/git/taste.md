# Git Preferences

- No AI/agent attribution in commits or the repo — explicitly prohibited by the owner: no Co-authored-by trailers, no AI mentions in commit messages. A commit-msg hook rejects `agent`, `cursor`, `codex`, `llm`, `bot`, `claude`, and `Hallmark` — as substrings, inside words too (`bot` trips on "both", as in "resolved on both sides"), so pre-screen every commit message against the hook's regex before committing; use the existing author identity and no attribution trailers. Confidence: 1
- Prefers new commits over `git commit --amend`. Confidence: 0.75
- Dispatches commits from within the worktree for the feature branch (never committing directly on main). Confidence: 0.7
- New worktrees are cut from current `main` (not from parked feature branches), using the `.worktrees/feature/<topic>` directory convention with a matching branch name — e.g. `.worktrees/feature/weather-panel` on branch `feature/weather-panel`, created via `git worktree add .worktrees/feature/weather-panel -b feature/weather-panel main`. A second worktree root exists for superpowers-dispatched sessions: `~/.config/superpowers/worktrees/<repo>/feature/<topic>` (e.g. sysc-shell's `feature/panel-backdrop-blur` lives there) — when hunting in-flight work, check both roots. Confidence: 0.75
- Docs-on-main rule: design/plan docs (`docs/plans/`), the plans register, and bd tracker state (`.beads/issues.jsonl`) commit directly to main — the sanctioned exception to the worktree-only commit rule; feature code still commits only from its worktree. Tracker JSONL changes made as part of feature work instead commit on the feature branch, ideally riding in the same commit as the code whose state they describe (the AGENTS.md pairing); a standalone tracker commit in the worktree is the fallback. Confidence: 0.6
- Committing from a `.worktrees/` worktree trips bd's commit hook — it needs the primary tracker DB, and without it the commit is blocked. The working pattern (used for every commit in the weather-panel slice) is `BEADS_DB=/home/nomadx/sysc-shell/.beads/beads.db git commit ...` run inside the worktree. Confidence: 0.8
- After committing — especially when the commit stages more than the files named — inspect `git show --stat` to catch rode-along content (bd auto-staging the tracker JSONL into a docs commit is the recurring case) and verify it (e.g. JSONL line count against the DB) before moving on. Confidence: 0.6
- Don't chain the test gates and the commit in one shell pipeline with `| tail`-style filters — exit-status masking let a commit land with failing tests once. Run the gates as separate commands and commit only after they pass (or `set -o pipefail` first). Confidence: 0.7
- Pre-merge safety assessments are evidence-based, not opinionated: check worktree cleanliness, main's divergence and file overlap since the branch point, run a trial merge (`git merge-tree --write-tree`) to surface conflicts before proposing any resolution, diff `go.mod`/`go.sum` for dependency changes, re-run the full gate suite fresh (build, every touched package with `-count=1`, `go vet`, `gofmt -l`), and review any foreign commits (another concurrent session's work) on their own merits — keep legitimate ones that come with their own tests. Confidence: 0.7
- Deliver merge verdicts as a blunt call backed by an evidence list, with process state kept separate from technical readiness: an open, deferred live/hardware gate recorded in bd does not block a merge — it becomes the post-merge remainder, and merging may precede the commissioned audit when same-branch development was the owner's call (precedent: the network-panel merge with its gate deferred). Close by offering to execute the merge. Confidence: 0.6
