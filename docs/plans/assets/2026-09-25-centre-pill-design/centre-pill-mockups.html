One centre element for time, date and the SYSC mark

Five ways to merge the clock, date and wordmark into a single control that opens the control centre. Sizes and colours are the shell's own: the default bar (40 px body, 28 px pills), Inter Variable at 15 px, and the fallback palette's real tokens. Option A is now built; the first section compares the shell's render with this page.

What's wrong with the current centre

The layout you described (time, mark, date) at 2×. The hatched area is width the time pill holds but doesn't use.

  1. 1The time pill is sized for the date. clockFloorFor in internal/shell/widget.go gives every clock the width of "Wed 30 Sep" when two clocks share the centre with a wordmark. "15:04" sits in a pill about 35 px too wide, so its padding doesn't match any other pill on the bar.
  2. 2The mark is heavier than everything around it. At ImageH 19 it fills most of the pill's text band, and nearly twice the cap height of Inter 15 (about 11 px). It sits outside the pills with no chrome, so it doesn't line up with them.
  3. 3Three objects, but only one does anything. Only the bare mark carries panelControlCenterAction. The clock pills look like buttons but have no action, and the mark has no hover or open state because it isn't in a capsule.
  4. 4Gaps don't match. The bar puts 4 px between items, capsules pad 6 px inside, and the mark has no padding at all. Each edge of the group ends up with a different spacing.

Concepts

Each one is a single control with one hit target, one accessible name ("Control centre") and one set of hover, focus and open states. They're shown at 2× and follow the palette selected above.

Concept A in every state

The states A has to handle, at 1.6×. Rest, hover, focus and media are built. "Open" (an accent wash and a stronger outline while the control centre shows) is not built yet: the bar has no signal for an open panel.

Changes that apply to every concept

  • Drop the width floor on the time. Tabular figures already stop the time jumping from minute to minute. Keep a floor on the date only, sized to its own widest string, so the pill only changes width when the weekday changes.
  • Size the mark to the text's cap height inside the pill, 9–11 px instead of 19. It stays recognisable because the SYSC letterforms are blocky and wide (aspect 7.27).
  • Make the whole element one button. Put the control-centre action, the accessible name and the tooltip (full date, e.g. "Thursday 25 September 2026") on the outer capsule, so the time, date and mark all open the control centre.
  • Use one padding value at both ends and let the gap inside the pill carry the rhythm. The bar's 4 px spacing then only appears between separate controls.
  • Decide where media goes. Inside the pill, media is part of the same control, but the pill gets wider and the mark moves off centre. As its own pill to the right, the centre element stays still and media stays a separate control. Concepts A, B, C and E show it inside; D has to keep it outside.
  • Layout: once the mark is inside a group, arrangeAnchoredWordmark no longer triggers, because it looks for a top-level KindWordmark in the centre. The pill is then centred by the normal arrangeBarSections path. That's fine as long as the pill's width is stable, which the first change above makes sure of.

Recommendation

A is built on PR #13's branch. It fixes all four problems, reads clearly as the bar's main control, and uses only parts the renderer already has: capsule Stroke/StrokeFill, KindSeparator, and a wordmark node inside a group. B is the next step up if the mark feels too quiet at 11 px. The plate uses the existing FillSoft wash.

E is the one to try if you want a signature element. It's the only option whose shape shows what it does: the control centre grows out of the tab. It costs a renderer change and a geometry change, so it makes more sense as a follow-up once A is in place.
