# Documentation and promo assets: capture design

Status: design approved by the owner 2026-10-09.

## Goal

A local folder of screenshots and video of sysc-shell, its launcher and the plugins, for the documentation
website and for promotion (Reddit posts and the like), that can be regenerated after a UI change and
carries no personal data. The sysc-terminal wallpaper video is the headline asset: nothing else turns
terminal art into a wallpaper, and no video of it exists yet.

Plugin screenshots are not part of this: they are generated by sysc-plugins (`make captures`, merged in
sysc-plugins#143 and #144) and are copied into the folder, not regenerated here.

## Decisions

| Question | Decision |
|---|---|
| Where the assets live | `/home/nomadx/sysc-assets` on the desktop. Local, not a repository. The laptop holds scratch output only |
| Where captures run | The laptop test bench: 1920x1080 at 1.25 scale, Go installed. It builds its own scratch worktree of `origin/main` (never the stale `~/sysc-main-test/shell-main`) |
| Scale | 125% (`ui.Scale120(150)`), the laptop's real scale |
| Fixture scenes | Gated tests in `internal/shell`, not a new command: they reuse the existing registry, panel and drain helpers and ship nothing in the binary |
| Backdrop | A real wallpaper behind every fixture panel, blurred with the shell's own `render.Blur`, not the flat colour `writeCardPNG` uses |
| Terminal art | Real session only. `sysc-terminal` is a separate live process driven through gslapper; the shell does not render the effect |
| Personal data in real-session captures | A clean-state step before recording plus a manual review checklist. No separate fixture session |

## Lanes

### A. Fixture scenes

`internal/shell/capture_*_test.go`, each skipped unless `SYSC_ASSETS_DIR` is set (the existing
`SYSC_*_PNG_DIR` gates are the pattern). A shared helper opens a real panel on a `Registry` with fixture
state, configures it at 125%, renders it with `Callbacks.Render`, composites it over a named backdrop with
blur behind it, and writes `$SYSC_ASSETS_DIR/shell/<surface>/<name>.png`.

Scenes, one representative state each unless noted:

- control centre: home, calendar, notifications, and each other page
- settings: several sections
- wallpaper panel; Terminal Art panel (controls only)
- system monitor; process detail
- launcher: browse and query
- notification card, toasts, OSD, tooltips, bar, lock screen

All identity is injected: `Registry.controlIdentity`, `machineFacts`, the wallpaper library snapshot and the
launcher entries. A fixture contains no real user, host, network, device or path.

### B. Real-session captures

Recipes in `sysc-assets/recipes/`, run over SSH on the laptop. They prepare a clean state (no real
notifications, tray items or network names), then take `grim` stills of the desktop with panels open, a
`wl-screenrec` video of the terminal-art wallpaper, and one backdrop still of the wallpaper alone. Each
recording is reviewed against a checklist before it enters the folder.

### Orchestration and manifest

`scripts/capture-assets --host laptop [--dry-run]` mirrors `scripts/deploy`: it checks that the laptop's
scratch worktree contains `origin/main`, runs lane A there, and rsyncs the results to the desktop folder.
`sysc-assets/manifest.json` has one row per file: path, kind (`fixture` or `real-session`), the scene or
recipe that made it, shell revision, scale, pixel size, date and a one-line description. A checker fails when
a file has no row or a row has no file.

## Open details the plan must settle

- Capturing the backdrop without the bar (hide the bar, or crop it out).
- How lane A obtains a blurred backdrop at panel scale from one wallpaper still.
- The clean-state step for lane B and its checklist.

## Testing

- Each scene lays out and paints, and its output is non-empty and the expected size; a normal `go test`
  writes no files.
- The manifest checker runs inside `scripts/capture-assets`.
- Lane B is checked by the review checklist; it cannot be unit tested.

## Out of scope

Animated or interactive fixture captures, hover and focus states, a published website, any change to the
shell's behaviour, and plugin screenshots.
