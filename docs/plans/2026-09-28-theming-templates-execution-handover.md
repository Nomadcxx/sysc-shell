# Theming template completion — execution handover

Commission the replacement of the stub `.tpl` files in `internal/theming/templates/` with real,
app-correct theme output, so their settings toggles can be turned on. Tracker: work items hang off
`sysc-405` (the GH#7 gate); the gate itself shipped on `fix/audit-tranche`.

## What already exists (do not rebuild)

- `theming.Complete(name)` (`internal/theming/catalog.go`) backed by `completeTemplates`, currently
  `{"niri": true}`. Only complete templates get settings toggles
  (`internal/settings/registry.go addTemplateEntries`) and only complete templates apply
  (`internal/theming/enabled.go applyOnce`); incomplete behaves as off, including un-applying older
  stub writes. Adding a template = verify, then add its name here.
- Apply machinery is done and tested: `writeTarget` maps names to live config paths, marker header
  (`# generated by sysc-shell — do not edit`) guards never overwrite user-edited files, temp+rename
  swap, per-app reload signals where they exist. Mechanism tests in `enabled_test.go` use
  `markTemplatesComplete`.
- The token model passed to templates today: `Primary`, `Surface`, `Outline`, `Mode` only
  (see `niri.tpl` for the only real example).

## Scope per template

1. Learn the app's real theme format — every one is different: alacritty TOML `[colors.*]`, foot ini,
   ghostty `key=value`, kitty `.conf`, wezterm Lua, starship TOML `palette`, helix `.toml` theme,
   kcolorscheme `.kcson`, btop and cava theme files, emacs `deftheme` elisp, scroll theme, qt
   `kdeglobals`, gtk3/gtk4.
2. Extend the render data once for the terminal family: full ANSI-16 palette, background, foreground,
   cursor, selection, bright variants. Terminals share ~90% of fields; do them as one cluster off a
   single token extension.
3. Write the `.tpl`, one golden render test per app (input palette → expected file), plus the existing
   round-trip mechanism test with `markTemplatesComplete(t, name)`.
4. Verify the reload signal (or document that a restart is needed) and flip `completeTemplates`.

## Disposition rule

If an app cannot be themed correctly by writing the one file `writeTarget` points at, delete the
template and its `writeTarget` case rather than shipping a half-theme. gtk3/gtk4 (and possibly qt)
are the likely casualties: they want a full named theme, not a colour drop-in. Decide before writing
them — YAGNI beats a plausible-looking file that renders an app ugly.

## Order (mirrored in bd)

Token extension → terminal cluster (alacritty, foot, ghostty, kitty, wezterm, starship) →
non-terminal cluster (btop, cava, helix, kcolorscheme, emacs, scroll) → gtk/qt disposition.
Each cluster task exits by flipping `completeTemplates` with golden tests green; nothing lands
half-complete.

## Constraints

- Go only; no new dependencies without approval. Go `text/template` is sufficient.
- Never weaken the unmarked-file guard, the marker header, or the temp+rename swap.
- `gofmt`/`vet`/`go test -race -count=1 ./...` gates; the live check for each app means opening the
  real app with the generated file, not just the unit test.
